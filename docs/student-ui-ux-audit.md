# SkyLab 學生端 UI／UX 稽核與流程化改版提案

> 稽核日期：2026-07-21  
> 對象：第一次登入、不了解 VM／LXC／GPU 等術語的學生  
> 核心原則：學生不需要先理解平台架構，只需要知道「我現在要做什麼」以及「下一步是什麼」。

## 1. 結論先行

目前學生端最大的問題不是單一按鈕或配色，而是**角色資訊架構失焦**。

- 一般學生登入後，側欄目前會出現 **27 個導覽入口**，另有帳號設定。
- 學生會看到資源管理、模板管理、審核、網路、系統管理、監控，以及可觀看其他學生畫面的「虛擬教室」等教師／管理者功能。
- 現有前端只對 3 個 AI 管理頁使用 `adminOnly` 隱藏；其餘多數管理路由只要登入就能進入。後端即使會拒絕請求，學生仍然會先遇到空畫面、403 或看不懂的功能。
- 「快速建立」和「完整申請」是兩條近似但規則不同的入口；學生不知道應該選哪一條。
- 完整申請表同時呈現類型、模板、帳密、CPU、RAM、硬碟、GPU、時段、月曆、理由、摘要與 AI 助手，認知負荷過高。
- 首頁偏向「展示內容」，沒有把「繼續上課、建立環境、查看進度」三個高頻任務放在最明顯的位置。

學生使用資源有三種本質不同的情境，介面必須先分流：

1. **上課**：老師已分發課堂機器，學生只要進入課堂並開啟機器。
2. **下課練習**：沿用老師分發的同一台課堂機器，開機後繼續上次進度。
3. **自主研究**：學生才需要自行提出新機器申請，說明用途、資源與期限。

三種情境不應共用同一個「申請資源」入口。建議把學生端改成 4 個主要導覽：

1. **首頁**：顯示下一件該做的事。
2. **我的課程**：上課與下課後練習都從課程進入，使用老師分發的機器。
3. **我的環境**：查看課堂機器與自主研究機器；只有研究情境提供「申請新機器」。
4. **申請進度**：只處理等待、失敗、補件與完成通知。

AI API、外觀與其他低頻能力放入「更多」或個人選單；所有教師／管理者入口不應出現在學生介面。

## 2. 稽核範圍與判斷方式

本次依前端路由、側欄角色過濾、頁面元件、操作文字、空狀態與錯誤狀態進行學生視角靜態稽核。主要依據：

- [App.jsx](../frontend/src/App.jsx)：登入後路由與角色限制。
- [Sidebar.jsx](../frontend/src/components/Sidebar/Sidebar.jsx)：學生實際可見的導覽項目。
- `frontend/src/pages/personal`：申請、資源、帳號與首頁。
- `frontend/src/pages/personal/dashboard`、`classroom`、`ai/ai-api`：學生可能使用的課程與 AI 功能。

目前環境沒有可連線的互動瀏覽器，因此本輪未完成「真實學生帳號登入後」的逐像素與鍵盤走查；建議實作前再用學生、教師、管理員三種測試帳號各跑一次權限與任務測試。這不影響本報告指出的路由、角色、文案與流程問題。

## 3. 全站層級的主要問題

### 三種學生情境必須先分流

| 情境 | 資源從哪裡來 | 學生真正需要做的事 | 不該要求學生做的事 | 正確的主要 CTA |
|---|---|---|---|---|
| 正在上課 | 老師預先分發 | 找到今天的課、確認機器已就緒、進入操作 | 申請、選 VM/LXC、調 CPU/RAM、填申請原因 | `進入今天的課堂` |
| 下課後練習 | 沿用該課程已分發的機器 | 開機、回到上次進度、在允許期限內練習 | 重新申請或重新建立另一台機器 | `開機並繼續練習` |
| 自主研究 | 學生提出新申請 | 說明研究用途、需要的能力與使用期限、送審 | 一開始就理解平台所有基礎設施欄位 | `申請研究機器` |

這個分流也必須存在於資料與狀態上。每台機器應清楚標記 `課堂分發` 或 `自主研究`，避免學生誤刪課堂機器、把課堂配額與研究配額混為一談，或在下課練習時重複申請。

#### 情境 A：正在上課

```text
首頁「今天正在上課」
→ 進入課堂
→ 顯示老師分發的機器與「已就緒／準備中」
→ 開啟桌面或終端機
→ 依老師步驟完成練習
```

如果老師控制統一開機，學生只看狀態；如果允許學生自行開機，畫面只顯示一個「啟動課堂機器」。課堂頁不要混入自主研究申請。

#### 情境 B：下課後自己練習

```text
首頁「繼續上次課程」或我的課程
→ 選擇課程
→ 顯示同一台課堂機器與資料保留期限
→ 開機並繼續練習
→ 離開時關機（保留資料）
```

此流程要清楚區分：`關機` 會保留資料、`重置課堂環境` 會清除練習變更、`課程到期回收` 由老師或系統控制。

#### 情境 C：自主申請研究機器

```text
首頁或我的環境「申請研究機器」
→ 選研究用途
→ 選系統推薦的環境能力
→ 填研究名稱與使用期限
→ 確認配額與審核方式
→ 送出申請
→ 等待審核／建立完成
```

只有這條流程需要出現申請狀態、理由、GPU、較長期限或自訂硬體。

### P0：學生導覽暴露大量非學生功能

側欄只替 AI 的「申請審核、金鑰管理、使用監控」加上 `adminOnly`。資源管理、審核、網路、教學管理、系統管理與監控仍會對一般登入者顯示。

影響：

- 學生難以辨認真正要使用的入口。
- 點進管理頁後遇到無資料或權限錯誤，會誤以為系統壞掉。
- 「虛擬教室」包含觀看學生畫面與直播功能，對學生可見會產生明顯隱私疑慮。
- 只靠前端隱藏不等於安全；前端路由守衛與後端權限仍需同時存在。

建議：

- 以 `student / teacher / admin` 建立明確 route manifest，而不是零散的 `adminOnly`。
- 學生側欄最多 4 個主要項目；教師與管理者使用不同導覽集合。
- 未授權路由顯示明確的 403 頁，不要靜默導回首頁，也不要先載入管理資料。

### P0：導覽依系統模組分類，不依學生任務分類

「申請、資源、審核、網路、AI 服務、教學、系統管理、監控與日誌」反映的是內部組織，而不是學生的心智模型。

學生心中通常只有：

- 我要上課／完成作業。
- 我要一台可用的練習環境。
- 我要連進我的環境。
- 我要知道申請到哪裡了。
- 我遇到問題需要協助。

建議導覽和首頁都直接使用這些任務語言。

### P1：相同需求有兩條建立路徑

首頁模板卡進入「快速建立」，「我的申請」又提供完整申請表；快速建立內還有「完整設定」跳轉。兩者在自動核准、密碼、進階設定與可調整項目上不同，但沒有先解釋適用情境。

建議合併成同一個 Wizard：

- 一般學生先選用途，系統自動推薦模板與規格。
- 只有選「我想自己設定」才展開 VM/LXC、CPU、RAM、GPU 等進階選項。
- 快速建立只是 Wizard 的預設路徑，不再是另一個產品入口。

### P1：狀態被拆散在「我的申請」與「我的資源」

建立中的項目會同時涉及申請狀態、開通狀態與資源卡片。學生需要理解 `審核中 → 已核准 → 開通中 → 已開通`，還要知道何時改去「我的資源」。

建議：

- 首頁提供一張統一的「進度卡」，顯示目前階段與下一個動作。
- 成功後直接提供「開啟環境」，不要求學生自行切頁尋找。
- 詳細歷史仍可保留在「申請進度」，但不作為日常操作中心。

### P1：術語、語言與危險操作不一致

- VM、QEMU、LXC、VMID、Root、Proxy、Tokens、Audit Logs、Port 等術語直接出現在學生介面。
- 同一側欄混用「User Settings / Log Out / Audit Logs」與繁體中文。
- 「刪除資源」與「歸還實驗機」的後果不同，但未形成一致的風險層級。

建議：

- 第一層使用「完整虛擬電腦」「輕量練習環境」；技術名稱放在補充說明。
- 學生介面預設全繁中，切換語言後才全站一起切換。
- 破壞性操作都顯示影響範圍、是否可恢復、資料保留方式與二次確認。

## 4. 逐頁／逐功能稽核

### 4.1 學生真正需要的頁面

| 頁面／功能 | 現況問題 | 新手風險 | 建議 |
|---|---|---|---|
| 登入、註冊、忘記密碼 | Email、校園帳號、Google 可能同時出現；沒有直接告訴學生「學校帳號應選哪個」 | 登入前就必須理解帳號系統差異 | 若學校 LDAP 可用，預設「使用校園帳號」並標示「學號即可」；Email／Google 收進「其他登入方式」 |
| 首頁 | 問候後先顯示課程推薦與模板；課程卡本身沒有進入動作；真正的待辦和建立進度不突出 | 看得到內容，但不知道第一步要按哪裡，也分不清課堂機器與自己申請的機器 | 頂部直接按三種情境呈現：`進入今天的課堂`、`開機並繼續練習`、`申請研究機器` |
| 課程推薦 | 使用靜態課程資料，卡片是展示型 `article`，沒有明確 CTA | 以為可以點擊，實際無法前往 | 串接已選課資料；整張卡可點，顯示「繼續第 3/5 個任務」 |
| 快速入門模板 | 「範本、克隆、版本」仍偏技術；且課堂需求與自主研究混在同一種模板入口 | 學生可能為了下課練習又建立一台新機器 | 課堂環境只能由課程卡進入；模板用途卡只服務自主研究，例如「一般程式開發」「資料分析」「AI / GPU」 |
| 快速建立 | 名稱、Root 密碼、公開存取、防火牆、HTTPS、自動網域、Port 與 AI 面板同時存在 | 原本的一鍵建立仍要求理解基礎設施，也沒有說明這是課堂機器還是研究機器 | 改成「申請研究機器」4 步 Wizard；平台可產生的名稱與密碼自動產生；公開網路放進進階設定 |
| 我的申請 | 使用桌面表格；一列同時呈現資源、系統、規格、時間、狀態、操作，細節再展開 | 手機閱讀困難；學生只想知道「還要等多久／我要做什麼」 | 改成狀態時間軸卡片；只在需要處理時顯示主按鈕，例如「補充原因」「重新嘗試」 |
| 完整申請表 | 單頁包含類型、模板／映像檔、帳密、硬體、GPU、時段、可用性月曆、原因、摘要、AI | 欄位過多、順序不符合學生決策方式；容易填到一半離開 | 先問用途，再套用預設；每步只做一個決策；進階硬體規格預設收合；最後一步集中檢查 |
| AI 申請助手 | 與右側摘要使用頁籤互相切換，另有全站浮動 AI | 兩個 AI 入口和摘要競爭注意力 | Wizard 內改成「幫我選」按鈕，只在用途／規格步驟出現；全站 AI 負責導覽與求助 |
| 我的資源 | 同頁混合配額、協作邀請、建立中卡片、資源卡、終端機／控制台、電源與刪除，也沒有先區分課堂分發與自主研究 | 可能誤刪課堂機器，或把下課練習誤解為需要重新申請 | 先分成「課堂機器」與「研究機器」；課堂卡主 CTA 為「開機並繼續練習」，研究卡才有申請、延期與刪除 |
| 資源卡電源選單 | 開機、關機、重啟、刪除都藏在三點選單；主畫面另有終端機／控制台 | 不懂關機與刪除差異，且開機後下一步不明顯 | 狀態決定單一主 CTA；執行中顯示「開啟」，關機時顯示「啟動」；刪除移至詳細設定底部 |
| 資源詳細頁 | 有總覽、監控、規格、快照、操作紀錄、進階設定 6 個頁籤 | 進入後像管理主控台，不像學生工作區 | 預設只留「使用」「備份」「設定」3 區；監控與紀錄收進「技術資訊」 |
| 資源總覽 | 連線資訊、系統資訊、電源與多張資訊卡並列 | 重要的「如何開始用」不一定最突出 | 最上方固定顯示「開啟控制台／複製 SSH 指令」與連線是否就緒 |
| 資源監控 | CPU、記憶體、磁碟與多時間區間圖表偏管理用途 | 新手不知道圖表和自己的問題有何關係 | 預設只顯示「環境是否正常」；完整圖表放入技術資訊 |
| 規格調整 | 學生與管理員共用元件，管理員可直接更新，學生需送審 | 介面行為可能因角色不同而難以預測 | 學生只顯示目前規格、推薦範圍與「申請更多資源」流程 |
| 快照 | 同時提供建立、還原、刪除與重置初始狀態 | 容易混淆「快照還原」和「全部重置」 | 改成「建立還原點」；將「重置課堂環境」獨立為高風險操作並說明會失去哪些資料 |
| 操作紀錄 | 表格偏稽核用途 | 對一般學生價值低，增加頁籤數 | 放入「技術資訊」，預設只顯示與錯誤排查相關的最近事件 |
| 進階設定 | 目前內容很少但占一個一級頁籤 | 形成空洞導覽 | 與規格合併成「設定」 |
| 課程學習 | 需要先展開學習路徑，再點房間；顯示房間、題數、難度等多種資訊 | 不確定應從哪個房間繼續 | 預設直接突出「繼續上次進度」；已完成、未解鎖與下一個任務清楚區隔 |
| 課程房間 | 左任務、中教材、右 VNC 三欄，頂部另有啟動／歸還 | 在小螢幕或第一次使用時不知道先啟動機器還是先讀教材 | 明確流程：啟動環境 → 閱讀步驟 → 操作 → 提交答案；每階段只突出一個下一步 |
| AI API | 同頁包含 4 張統計卡、4 個頁籤、申請、金鑰操作、紀錄與用量 | 不是所有學生都需要；金鑰生命週期複雜 | 放入「更多服務」；首次使用以 3 步流程呈現：說明用途 → 申請 → 複製範例程式 |
| 帳號設定 | 個人資料、密碼、外觀與危險區域同層；自訂背景選項很多 | 低頻外觀設定比核心學習功能更精細 | 保留於個人選單；刪除帳號與外觀分離，刪除前說明課程資料與資源如何處理 |
| 語言切換 | 顯示語言選單，但部分 UI 仍硬編碼中英混合 | 使用者以為已切換完整語言 | 在 i18n 完成前先標示 Beta，或暫時只提供完整支援的語言 |
| 全站浮動 AI | 每頁皆出現，申請表內又有另一個 AI 助手 | 重複入口、遮擋內容、學生不清楚兩者差異 | 全站 AI 限定「導覽與求助」；表單內改成情境式「幫我選」 |

### 4.2 目前對學生可見，但應移出學生端的頁面

| 目前入口 | 判定 | 原因／處理方式 |
|---|---|---|
| 資源管理 `/resource-mgmt` | 學生隱藏 | 全域資源管理屬管理員／教師；學生只需要「我的環境」 |
| 模板管理 `/templates` | 學生隱藏 | 模板建立、版本與管理不屬學生任務；學生只看用途化的可用模板 |
| GPU 管理 `/gpu-mgmt` | 學生隱藏 | GPU 庫存與映射是管理工作；學生只在需求步驟選「需要 GPU」 |
| 申請審核 `/request-review` | 學生隱藏 | 審核者功能 |
| 批量審核 `/batch-review` | 學生隱藏 | 審核者功能 |
| 防火牆 `/firewall` | 學生隱藏或情境化 | 若學生可自助開 Port，只在特定環境的「公開服務」流程出現 |
| 反向代理 `/reverse-proxy` | 學生隱藏或情境化 | 改成「發布我的網站」Wizard，不暴露 Proxy 術語 |
| 網域管理 `/domain` | 學生隱藏或情境化 | 與「發布網站」合併，不作為全域導覽 |
| IP 管理 `/ip-management` | 學生隱藏 | 位址池與分配屬管理工作 |
| 閘道 VM `/gateway` | 學生隱藏 | 基礎設施管理功能 |
| 班級管理 `/class-management` | 學生隱藏 | 教師功能，且目前標示待開發 |
| 上課機器模板 `/course-template-management` | 學生隱藏 | 教師建立課程環境功能，且目前標示待開發 |
| 虛擬教室 `/classroom` | **學生隱藏（P0）** | 頁面可列學生、觀看 VM、直播；有隱私與越權風險。學生觀看老師直播應由全站直播橫幅進入唯讀視窗 |

## 5. 建議的學生端資訊架構

```text
首頁
├─ 正在上課：進入今天的課堂
├─ 下課練習：開機並繼續上次課程
├─ 自主研究：申請研究機器
├─ 申請／建立進度
└─ 今天的待辦與通知

我的課程
├─ 今天上課（老師已分發機器）
├─ 下課後練習（沿用課堂機器）
├─ 即將開始
└─ 已完成

我的環境
├─ 課堂機器（依課程分組）
├─ 自主研究機器
├─ 建立中／等待審核
├─ 申請研究機器（Wizard）
└─ 環境詳情：使用／備份／設定

申請進度
├─ 需要我處理
├─ 等待中
└─ 已完成

個人選單
├─ AI API（有權限或已啟用才顯示）
├─ 帳號與密碼
├─ 外觀與語言
├─ 說明與回報問題
└─ 登出
```

### 首頁排序規則

首頁不要固定先放推薦內容，而應根據急迫性排序：

1. 需要學生處理的失敗／補件。
2. 正在上課或即將到期的環境。
3. 尚未完成的課堂任務。
4. 自主研究機器的申請與審核進度。
5. 推薦內容與更多服務。

## 6. 流程化方案：自主申請研究機器

建議從目前長表單改成 4 步驟：

> 課堂上課與下課練習不進入此 Wizard，兩者都直接使用老師已分發的課堂機器。

### 第 1 步：研究要做什麼？

選項使用任務語言：

- 一般程式開發
- 資料分析／運算
- AI 或 GPU 研究
- 我想自己設定

此步只決定推薦策略，不顯示 VM／LXC。

### 第 2 步：選擇環境

- 顯示老師指定或系統推薦的 2～3 個選項。
- 每張卡只說明「適合什麼」「已包含什麼」「預計建立時間」。
- 技術規格放「查看詳細規格」，不作為主要比較內容。

### 第 3 步：研究名稱與使用期限

- 預設提供「7 天」「30 天」「本學期」等研究情境快捷選項。
- 環境名稱自動產生，可選擇修改。
- 網路、CPU、RAM、硬碟、GPU、密碼等收在「進階設定（大多數人不用改）」。
- 能由平台安全產生的密碼，建立完成後再交付，不在申請前要求學生自行設定。

### 第 4 步：確認並送出

清楚回答：

- 會建立什麼？
- 何時可用？
- 何時回收？
- 會使用多少配額？
- 送出後下一步是什麼？

送出成功後，不只顯示 Toast；應停留在成功頁並呈現自主申請的進度時間軸：

```text
已送出 → 等待審核 → 建立研究環境 → 可以開啟
```

## 7. 文案與元件規則

### 每頁只能有一個主動作

- 首頁：「繼續課程」或「建立環境」，依使用者狀態決定。
- 環境卡：「開啟環境」或「啟動環境」。
- 申請卡：「查看進度」；只有需要處理時才替換為「修正並重新送出」。

### 狀態一定要搭配下一步

不要只寫「開通失敗」，要寫：

> 建立環境時發生問題。你的申請資料已保留，可以直接重新嘗試。

並提供單一按鈕「重新嘗試」。

### 技術名詞採雙層呈現

第一次出現：`輕量練習環境（LXC 容器）`。  
後續主要介面只使用：`輕量環境`。  
技術資訊區才顯示：`LXC、VMID、節點、映像檔`。

### 進階設定採漸進揭露

符合以下任一條件才顯示：

- 使用者主動展開。
- 課程或模板要求學生做決策。
- 系統偵測預設值無法完成需求。

## 8. 實作優先順序

### P0：先避免誤入與越權

- 建立角色導覽 manifest。
- 隱藏所有教師／管理者頁面。
- 對路由加入 student／teacher／admin guard。
- 後端逐一確認對應權限，尤其是虛擬教室、觀看、直播、審核、系統與網路 API。
- 新增 403 頁與角色切換自動化測試。

### P1：降低新手完成任務的成本

- 合併快速建立與完整申請為同一個 Wizard。
- 首頁改成任務導向，優先顯示「下一步」。
- 統一申請與建立進度。
- 資源卡固定單一主 CTA。
- 課程房間加入明確階段與手機版單欄流程。

### P2：一致性與長期品質

- 完成所有學生文案的 i18n。
- 建立術語表、狀態表與破壞性操作規格。
- 將 AI 助手重新分工為全站求助與情境式推薦。
- 加入學生可用性測試與事件分析。

## 9. 驗收標準

建議用以下指標判斷改版是否真的更簡單：

- 新學生登入後 10 秒內能指出「如何開始課程」與「如何建立環境」。
- 學生主導覽不超過 4 個主要入口。
- 學生帳號看不到任何教師／管理者頁面與 API 資料。
- 80% 以上學生不展開進階設定，也能完成環境建立。
- 建立環境的主要決策不超過 4 步，每步只有一個主要 CTA。
- 手機寬度 360 px 下，不需要橫向捲動表格才能完成核心任務。
- 失敗、補件、等待與完成狀態都能回答「接下來要做什麼」。
- 5 位第一次使用的學生中，至少 4 位能在沒有口頭提示下完成指定任務。
