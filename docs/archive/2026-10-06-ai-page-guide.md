# AI 助手：頁面導覽與彈出視窗說明

助手的畫面說明從「一句話講這頁做什麼」擴充成完整導覽，涵蓋五件事：
頁面用途、什麼時候需要這頁、主要功能怎麼用、每個彈出視窗怎麼填、要做的事不在這頁時該改去哪。

內容寫在 `backend/app/ai/contextual_help/surface_guides.py`，依 surface id 併進 `surfaces.py` 的畫面定義。
`when_to_use`、`features` 每頁必填；`dialogs` 列出會跳出的表單或需要輸入的確認框；`related` 只能指向導覽目錄裡的路徑。
同一頁上只有部分身分看得到的視窗（例如教師才有的「轉成範本」）以 `access` 標記，學生的導覽不會提到。

問題分類（`intent.py`）新增兩種，答案由 `guide.py` 直接照定義排版，不呼叫模型：

- `page_guide`：「這頁怎麼用」「介紹這個頁面」「這裡可以做什麼」。
- `dialog_help`：點名某個視窗（「申請延長到期日怎麼填」），或只說「這個視窗怎麼填」時列出這頁所有視窗。

指著某一格或講出按鈕名稱問的（「這格怎麼用」「測試怎麼用」）仍是欄位說明，不會變成整頁導覽。
簡短的頁面說明（`page_overview`）仍由模型改寫，情境多帶 `when_to_use` 與相關頁面，模型只能從相關頁面清單裡指路。
回應新增 `related`，前端顯示成可以直接點的按鈕；只列使用者有權限的頁面。
導覽助手的頁面目錄也帶上各頁的 `when_to_use`，依使用者的處境挑頁面，而不只比對關鍵字。

前端助手面板的頁名旁多了「頁面導覽」按鈕，空白對話的第一個建議問題也是「這個頁面怎麼用？」，兩者都直接走畫面說明。
在教學頁問「這頁怎麼用」、或問「跳出來的視窗」時，前端會先交給畫面說明，不會被帶去建立班級。
功能索引（「有哪些功能」）每一項改列「什麼時候用」。

新增畫面時（測試會紅燈提醒）：

- 在 `surfaces.py` 加畫面定義，在 `surface_guides.py` 加同 id 的導覽。
- 視窗標題與開啟按鈕寫畫面原文，測試會比對 zh-TW 語系檔；標題帶插值時加進 `_DERIVED_DIALOG_TITLES`。
- 不寫版面位置（上方、左側、右上角），只用按鈕與分頁上的文字指認。
- 欄位限制要對得上前端驗證，寫之前先看元件的 validate。
