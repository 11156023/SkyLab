# 資源排程

「資源排程」設定所有 PVE 連線共用的放置、超配與排程開機參數：平台如何替新機器挑選節點、如何替繁忙的節點扣分、使用時段開始前如何先把機器開起來，以及練習時段多長。側欄：管理員設定 → 資源排程。路徑：`/scheduler`。

## 誰可以使用

只有管理員可以使用。

## 開始之前

- 在 [PVE 管理](/zh-TW/manual/pve-connections)至少要有一筆已同步的 PVE 連線。各叢集自己的 pool、storage 與網段在該連線上設定，不在這裡。
- 對某個數值沒有把握時，維持預設值即可。

## 操作步驟

### 調整放置與超配

1. 在「放置與超配」卡片設定「CPU 超配比」、「Disk 超配比」、「RAM 超配比」與「換節點成本」。
2. 按「儲存排程設定」。

「CPU 超配比」2 表示每顆實體核心最多分配 2 個 vCPU；「Disk 超配比」1 表示磁碟不超配。「RAM 超配比」1 表示記憶體不超配，最多 2：分配給機器的記憶體總量可達實體記憶體的兩倍，但實際用量仍不能超過實體記憶體。「換節點成本」越高，平台越傾向把機器留在原本的節點。這張卡片標示「立即生效」：儲存後下一次放置就會採用新值。

![調整放置與超配（圖中編號對應上方步驟）](/manual-shots/zh-TW/scheduler/s01.webp)

### 調整繁忙節點的扣分方式

1. 在「資源評估閾值」卡片調整各項餘裕、閾值與權重。
2. 按「儲存排程設定」。

平台替新機器評分節點時，這些數值決定繁忙的節點要扣多少分。每個「警戒」值是開始扣分的位置，之後扣分逐漸增加，到對應的「上限」或「高位」值時扣到最多。這張卡片同樣「立即生效」。

![調整繁忙節點的扣分方式（圖中編號對應上方步驟）](/manual-shots/zh-TW/scheduler/s02.webp)

### 設定排程開機

1. 在「排程開機與時段」卡片設定「提前開機（分）」、「開機批次大小」、「批次間隔（秒）」與「時段寬限（分）」。
2. 按「儲存排程設定」。

使用時段開始前，平台會提前把機器開起來，一次一批、批次之間隔開一段時間，避免同時開機壓垮儲存。時段結束後，平台會再等候寬限時間才把機器關機。這張卡片標示「下個排程週期生效」。

![設定排程開機（圖中編號對應上方步驟）](/manual-shots/zh-TW/scheduler/s03.webp)

### 設定練習時段與到期提醒

1. 在「練習時段與到期提醒」卡片設定「練習時段（小時）」、「練習提醒（分）」與「到期提醒（小時）」。
2. 按「儲存排程設定」。

學生在使用時段以外自己開機時，機器會在練習時段結束後自動關機，結束前會先提醒。「到期提醒」只決定學生畫面多早顯示快到期警示；到期後的通知、關機與刪除由[資源政策](/zh-TW/manual/governance)的 TTL 生命週期負責。

![設定練習時段與到期提醒（圖中編號對應上方步驟）](/manual-shots/zh-TW/scheduler/s04.webp)

### 放棄未儲存的修改

1. 按儲存鈕旁的「還原」（有修改時才會出現）。
2. 表單會回到上次儲存的值。

有未儲存的修改時離開頁面，會先跳出確認提醒。

![放棄未儲存的修改（圖中編號對應上方步驟）](/manual-shots/zh-TW/scheduler/s05.webp)

## 欄位與選項

| 欄位 | 意義 | 備註 |
| --- | --- | --- |
| CPU 超配比 | 每顆實體核心可分配的 vCPU 數 | 1–8，預設 2 |
| Disk 超配比 | 相對實際容量可分配的磁碟空間倍數 | 1–5，預設 1（不超配） |
| RAM 超配比 | 分配給機器的記憶體總量相對實體記憶體的倍數；實際用量仍不能超過實體記憶體 | 1–2，預設 1（不超配） |
| 換節點成本 | 偏好讓機器留在原節點的程度 | 0–5，預設 0.15 |
| CPU 峰值餘裕 | 為 CPU 突增預留的空間 | 1–2，預設 1.1 |
| RAM 峰值餘裕 | 為記憶體突增預留的空間 | 1–2，預設 1.05 |
| LoadAvg 警戒 / 核 | 每顆實體核心的負載平均開始扣分的位置 | 0–4，預設 0.8 |
| LoadAvg 上限 / 核 | 每顆實體核心的負載平均扣到最多的位置 | 0.1–8，預設 1.5；必須大於「LoadAvg 警戒 / 核」 |
| LoadAvg 懲罰權重 | 負載平均扣分的比重 | 0–5，預設 0.9 |
| 磁碟爭用警戒占比 | 儲存占用開始扣分的位置 | 0–1.5，預設 0.7 |
| 磁碟爭用上限占比 | 儲存占用扣到最多的位置 | 0.1–2，預設 0.9；必須大於警戒占比 |
| 磁碟懲罰權重 | 磁碟爭用扣分的比重 | 0–5，預設 0.75 |
| CPU 峰值警戒占比 | CPU 占用開始扣分的位置 | 0–2，預設 0.7 |
| CPU 峰值高位占比 | CPU 占用扣到最多的位置 | 0.1–3，預設 1.2 |
| RAM 峰值警戒占比 | 記憶體占用開始扣分的位置 | 0–2，預設 0.8 |
| RAM 峰值高位占比 | 記憶體占用扣到最多的位置 | 0.1–3，預設 0.85 |
| 資源權重 CPU／RAM／Disk | 比較節點時各項資源的重要程度 | 各 0–10，預設 1 |
| 開機批次大小 | 每批開機的機器數 | 1–100，預設 5 |
| 批次間隔（秒） | 開機批次之間的間隔 | 0–600，預設 10 |
| 提前開機（分） | 時段開始前多早開機 | 0–120，預設 5 |
| 時段寬限（分） | 時段結束後等多久才關機 | 0–240，預設 30 |
| 練習時段（小時） | 在時段外開機的機器可運作多久 | 1–24，預設 3 |
| 練習提醒（分） | 練習時段結束前多久提醒 | 1–120，預設 30 |
| 到期提醒（小時） | 學生畫面多早顯示快到期警示 | 1–720，預設 24 |

LoadAvg 一律以實體核心計算：節點負載平均除以實際 CPU 數，不乘 CPU 超配倍率。

## 限制與注意事項

- 四張卡片共用一個「儲存排程設定」按鈕，有修改時才能按。
- 「LoadAvg 上限 / 核」不大於「LoadAvg 警戒 / 核」，或「磁碟爭用上限占比」不大於「磁碟爭用警戒占比」時，儲存會被拒絕。
- 平台的排程器每 60 秒執行一輪。每一輪會依使用時段開關機器、執行排程開機與自動關機、處理到期的申請單與刪除佇列、管理快速練習機器，並執行[資源政策](/zh-TW/manual/governance)設定的治理檢查（資源警告、TTL 生命週期、閒置偵測、挖礦偵測、快照清理）與平台健康檢查。後端有多個副本時，同一時間只有一個副本會執行排程器。
- 標示「下個排程週期生效」的設定，會在下一輪（60 秒內）開始採用。
- 節點的啟用與否和優先度在 [PVE 管理](/zh-TW/manual/pve-connections)逐節點設定，不在這裡。
